# QQ 农场飞牛 NAS 部署与变更说明

**应用名称：** QQ 农场  
**目标平台：** 飞牛 fnOS（x86）  
**当前版本：** V1.2.1  
**当前升级包内部版本：** `2026.10.7`  
**服务端口：** 无（仅飞牛统一网关 Unix Socket）  
**运行环境：** 内置（Node.js v22.23.3 单文件可执行程序），不依赖应用中心 Node.js  
**上游版本：** `20260928`（[liyangpengs/qq-farm-bot](https://github.com/liyangpengs/qq-farm-bot) `8303e7d`），安装包构建自本仓库提交 `aa85558`  
**维护日期：** 2026-10-12

## 1. 部署目标

V1.1.0 将 QQ 农场从 Docker 应用改为**飞牛原生应用**：

- 不再使用 Docker 镜像和容器。
- 不再开放 `3007` 或任何其他 TCP 端口。
- 只能通过飞牛应用中心的统一网关入口访问：

`/app/qq-farm-bot/`

访问前必须先登录飞牛；应用自身不再有独立的管理员账号、登录页和密码。

## 2. 应用运行配置

| 项目 | 配置 |
| --- | --- |
| 应用标识（appname） | `qq-farm-bot` |
| 运行方式 | 飞牛原生进程：单文件可执行程序 `server/bin/qq-farm-bot`（Node SEA） |
| 运行环境 | 内置官方 Node.js v22.23.3 linux-x64（要求 glibc ≥ 2.28，飞牛基于 Debian 12，glibc 2.36）；**不依赖**应用中心 Node.js |

## 3. V1.1.0 功能性修改

### 3.1 改为原生应用，去掉 Docker 与端口

- V1.2.0 起后端为单文件可执行程序 `server/bin/qq-farm-bot`（见第 5 节 V1.2.0），前端为 `server/web/dist`，游戏配置、图片、proto、wasm 在 `server/resources/`。
- `cmd/main` 负责 `start / stop / status`：启动前检查可执行文件是否完整，启动后等待 Socket 就绪；停止时先 `TERM`，15 秒后 `KILL`，并清理 Socket 与 PID 文件。
- 后端新增 `QQ_FARM_SOCKET`：设置后服务**只**监听该 Unix Socket，不再调用任何 TCP 监听。
- 原 V1.0 容器内的 Unix Socket 代理已删除：飞牛网关直接连到应用自己的 Socket。
- 未设置 `QQ_FARM_SOCKET`（源码开发）时，默认只绑定 `127.0.0.1:3007`。
- V1.1.1 起，飞牛原生包**在任何情况下都不会监听 TCP**：`cmd/main` 额外设置 `QQ_FARM_NO_TCP=1`，打包时还会写入标记文件 `server/core/FNOS_NATIVE`；两者任一存在时，若缺少 `QQ_FARM_SOCKET`，服务记录错误并直接退出，而不是回退到 `3007`。

### 3.2 飞牛网关适配（沿用 V1.0 思路并改为原生实现）

飞牛网关转发请求时保留 `/app/qq-farm-bot` 前缀：

- 后端入口统一剥离前缀，原有路由无需改动；`/app/qq-farm-bot` 会 301 到 `/app/qq-farm-bot/`。
- Socket.IO 路径：`/app/qq-farm-bot/socket.io`。
- 前端构建使用 `VITE_BASE=/app/qq-farm-bot/`：静态资源、Vue Router 基路径、Axios `baseURL` 都带网关前缀。
  - 与 V1.0 的相对资源路径（`./`）相比，绝对前缀在多级路由直接刷新时也不会白屏。
- 前端 `gatewayPath()`：变异作物图、活动资源、星砂说明图、宠物日记默认图。
- 后端 `gatewayPath()`：种子/道具图、土地等级图（`/land-assets/*.png`）、宠物日记资源。
- 微信扫码二维码继续通过 Axios 请求 `/api/wx-login/tasks/<task-id>/qr` 后转为 `blob:` URL 显示。

### 3.3 移除管理员登录与改密模块

访问控制已完全交给飞牛，不再需要 `DISABLE_ADMIN_AUTH` 开关，相关代码整体删除：

- 前端：删除登录页 `Login.vue`、用户 store、侧栏「退出登录」菜单与「我的 Token」区块、设置页「修改管理员密码」卡片、路由登录守卫和 401 跳转。旧地址 `/login` 直接重定向到首页。
- 后端：删除 `/api/login`、`/api/logout`、`/api/user/change-password`、`/api/user/me`、`/api/auth/validate`，删除令牌校验中间件、Socket.IO 令牌校验、`admin-store` 与 `auth-security`（登录限流）模块。
- 侧栏用户卡片改为显示当前飞牛用户（来自网关 Header，`/api/fnos/me`）。
- 默认仅允许飞牛管理员访问（HTTP 返回 403，Socket.IO 拒绝连接）；如需让普通飞牛用户使用，可把环境变量 `QQ_FARM_ADMIN_ONLY` 改为 `0` 并把桌面入口 `allUsers` 改为 `true` 后重新打包。
- 旧数据中的 `admin.json`、`login-attempts.json` 迁移时改名为 `*.unused` 保留，不再读取。

## 4. 数据迁移（从 V1.0.x Docker 版升级）

覆盖安装时：

1. `upgrade_init`：若存在并运行着旧容器 `qq-farm-bot`，执行 `docker stop`，并把其重启策略改为 `no`，避免旧容器继续占用 `3007`。**不删除容器和数据卷。**
2. `upgrade_callback`：若新数据目录还没有数据，则：
   - 通过 `docker volume inspect` 找到 `qq-farm-data`、`qq-farm-logs` 的实际路径（找不到时依次尝试 `/var/lib/docker/volumes`、`/vol*/docker/volumes`、`/vol*/@docker/volumes`）；
   - `cp -a` 复制到 `${TRIM_PKGVAR}/data` 与 `${TRIM_PKGVAR}/data/logs`；
   - 写入标记文件 `${TRIM_PKGVAR}/data/.migrated-from-docker`（记录来源路径），之后不会重复迁移。
3. 先卸载 Docker 版、再全新安装本版时，`install_callback` 也会执行同样的迁移。

确认新版本账号与配置都正常后，可手动清理旧 Docker 资源（可选）：

```bash
docker rm qq-farm-bot
docker volume rm qq-farm-data qq-farm-logs
```

> 若迁移失败或找不到数据卷，应用会按全新安装启动，原数据卷保持不变；可把卷中的文件手动复制到 `/vol*/@appdata/qq-farm-bot/data/` 后重启应用。

### V1.2.0 / 内部升级号 2026.10.6

**目标：** 安装包自带运行环境，不再依赖飞牛应用中心的「Node.js v22」（`nodejs_v22`）。

**依赖检查：**

- 生产依赖全部是纯 JS，没有原生模块：
  - 包括 express、socket.io、ws、axios、protobufjs、winston、pushoo、node-fetch、long；
  - 没有 `.node` 文件、`binding.gyp`，也不涉及 better-sqlite3、sharp 等。
- ws 的可选加速模块 `bufferutil` / `utf-8-validate`、node-fetch 的可选 `encoding` 在运行时用 `try/catch` 加载，打包时设为 external，缺失时自动回退纯 JS。
- 影响打包的写法：
  - `client.ts` 用模板字符串动态 `require` 入口。改为新增 `fnos/sea/entry.js`，用静态 `require`。
  - 账号运行在 `worker_threads` 中，需要单独的脚本文件（进程模式下用 `fork`）。
  - 资源路径依赖 `__dirname`。
  - 所有 TSDK 加解密都在运行时读取 `.wasm` 文件。

**方案：Node SEA（单文件可执行程序）**

- 打包流程（见 `fnos/sea/build-sea.sh`）：
  1. 下载官方 Node.js `v22.23.3` linux-x64，按 `SHASUMS256.txt` 校验；
  2. 用 esbuild 把后端打包成一个 CJS 文件；
  3. 用 `--experimental-sea-config` 生成 blob，再用 `postject` 注入官方二进制，得到 `server/bin/qq-farm-bot`。
- 账号 worker 单独打包为 `server/bin/worker.js`，由可执行文件用 `worker_threads` 加载。进程模式（`FARM_RUNTIME_MODE=process`）下，可执行文件以 `FARM_WORKER=1` 重新启动自身。
- 静态资源以普通文件放在可执行文件旁边：
  - `server/resources/`：gameConfig 与图片、proto、tsdk wasm；
  - `server/web/dist/`。
- `runtime-paths` 能识别 SEA 并按上述目录取资源。也可以用 `QQ_FARM_RESOURCE_DIR` / `QQ_FARM_WEB_DIR` / `QQ_FARM_WORKER_SCRIPT` 显式指定，`cmd/main` 会全部传入。
- 可执行文件内置 `QQ_FARM_NO_TCP=1`。即使环境变量和 `FNOS_NATIVE` 标记文件都不存在，缺少 Socket 配置时也会直接退出，绝不监听 TCP。
- 为什么不直接内置 `app/bin/node` 加 `node_modules`：两种方案体积相近，SEA 文件更少，并且可执行文件自带「禁止 TCP」限制，因此选择 SEA。如果日后遇到 SEA 不兼容的依赖，可以回退为内置 Node 方案。
- 兼容性：官方二进制最高需要 `GLIBC_2.28`、`GLIBCXX_3.4.21`。飞牛基于 Debian 12（glibc 2.36、libstdc++ 12），满足要求。

**其他修改：**

- `manifest` 删除 `install_dep_apps = nodejs_v22`。
- `cmd/main` 删除 Node 查找，直接通过 `runuser` 以应用用户启动 `server/bin/qq-farm-bot`。
- 统计数据（`stats/<账号>.json`）默认存到数据目录 `QQ_FARM_DATA_DIR`。V1.1.x 原生版会尝试写入只读的安装目录。
- 已安装的「Node.js v22」应用不会被自动卸载。本应用不再使用它，如没有其他应用依赖，可以自行卸载。
- 体积：
  - FPK 由约 22.9 MB 增加到约 62.6 MB，安装后约 149 MB；
  - 其中可执行文件约 124 MB，主要是 Node.js 运行时本身；
  - `resources` 约 21 MB，`web` 约 3.4 MB。

## 9. 后续维护建议

- 构建：在仓库根目录执行 `fnos/build.sh`（需要联网下载并校验官方 Node.js），产物与 `.sha256` 在 `fnos/out/`。升级内置 Node.js 时，设置 `NODE_SEA_VERSION`（仅限 v22 LTS 或更新的 LTS 版本）。
- 新增后端依赖时，确认它是纯 JS 且能被 esbuild 打包；如果带 `.node` 原生模块，`build.sh` 会报错终止。
- 新增前端图片、字体或下载文件时，避免直接使用以 `/` 开头的地址；应使用前端 `gatewayPath()`。
- 后端向前端返回本应用的资源 URL 时，使用后端 `gatewayPath()`；二维码这类由 Axios 再请求的 API URL 保持相对 `/api/...`。
- 本版本没有应用内登录：不要把 `app.sock` 通过其他方式（端口转发、反向代理）暴露出去。
- 合并上游代码后，重新扫描以 `/` 开头的资源路径，并确认上游没有重新引入登录/令牌相关代码。
- 每次发布都要提高 `fnos/qq-farm-bot/manifest` 中的 `version`。
