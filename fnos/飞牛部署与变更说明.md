# QQ 农场飞牛 NAS 部署与变更说明

**应用名称：** QQ 农场  
**目标平台：** 飞牛 fnOS（x86）  
**当前版本：** V1.1.1  
**当前升级包内部版本：** `2026.10.5`  
**服务端口：** 无（仅飞牛统一网关 Unix Socket）  
**上游版本：** `20260928`（[liyangpengs/qq-farm-bot](https://github.com/liyangpengs/qq-farm-bot) `1103b63`），安装包构建自本仓库提交 `1b873f1`  
**维护日期：** 2026-10-09

## 1. 部署目标

V1.1.0 将 QQ 农场从 Docker 应用改为**飞牛原生应用**：

- 不再使用 Docker 镜像和容器。
- 不再开放 `3007` 或任何其他 TCP 端口。
- 只能通过飞牛应用中心的统一网关入口访问：

`/app/qq-farm-bot/`

访问前必须先登录飞牛；应用自身不再有独立的管理员账号、登录页和密码。

## 2. 应用运行配置

| 项目 | 配置 |
| --- | --- |
| 应用标识（appname） | `qq-farm-bot` |
| 运行方式 | 飞牛原生进程（`node client.js`） |
| Node.js 运行环境 | 应用中心「Node.js v22」（`install_dep_apps=nodejs_v22`，安装时自动安装依赖） |
| 运行用户 | 生命周期脚本以 root 执行，服务进程通过 `runuser` 降权为应用用户 `qq-farm-bot` |
| 监听 | `${TRIM_APPDEST}/app.sock`（即 `/var/apps/qq-farm-bot/target/app.sock`），**无 TCP 监听** |
| 飞牛应用入口 | `/app/qq-farm-bot/`（`gatewayPrefix=/app/qq-farm-bot`，`gatewaySocket=app.sock`） |
| 访问控制 | 飞牛登录态 + 仅飞牛管理员（`X-Trim-Isadmin`），桌面图标 `allUsers=false` |
| 时区 | `Asia/Shanghai` |
| 数据目录 | `${TRIM_PKGVAR}/data`（`/vol*/@appdata/qq-farm-bot/data`） |
| 业务日志 | `${TRIM_PKGVAR}/data/logs` |
| 进程日志 | `${TRIM_PKGVAR}/app.log`（超过 10 MB 启动时轮转为 `app.log.1`） |
| 最低系统版本 | fnOS `1.1.3100`（统一网关要求） |

## 3. V1.1.0 功能性修改

### 3.1 改为原生应用，去掉 Docker 与端口

- 安装包内直接包含编译好的后端（`server/core`）、前端（`server/web/dist`）和生产依赖（纯 JS，无原生模块）。
- `cmd/main` 负责 `start / stop / status`：启动前检查 Node.js 运行环境，启动后等待 Socket 就绪；停止时先 `TERM`，15 秒后 `KILL`，并清理 Socket 与 PID 文件。
- 后端新增 `QQ_FARM_SOCKET`：设置后服务**只**监听该 Unix Socket，不再调用任何 TCP 监听。
- 原 V1.0 容器内的 Unix Socket 代理已删除：飞牛网关直接连到应用自己的 Socket。
- 未设置 `QQ_FARM_SOCKET`（源码开发）时，默认只绑定 `127.0.0.1:3007`。
- V1.1.1 起，飞牛原生包**在任何情况下都不会监听 TCP**：`cmd/main` 额外设置 `QQ_FARM_NO_TCP=1`，打包时还会写入标记文件 `server/core/FNOS_NATIVE`；两者任一存在时，若缺少 `QQ_FARM_SOCKET`，服务记录错误并直接退出，而不是回退到 `3007`。

### 3.2 飞牛网关适配（沿用 V1.0 思路并改为原生实现）

飞牛网关转发请求时保留 `/app/qq-farm-bot` 前缀：

- 后端入口统一剥离前缀，原有路由无需改动；`/app/qq-farm-bot` 会 301 到 `/app/qq-farm-bot/`。
- Socket.IO 路径：`/app/qq-farm-bot/socket.io`。
- 前端构建使用 `VITE_BASE=/app/qq-farm-bot/`：静态资源、Vue Router 基路径、Axios `baseURL` 都带网关前缀。
  - 与 V1.0 的相对资源路径（`./`）相比，绝对前缀在多级路由直接刷新时也不会白屏。
- 前端 `gatewayPath()`：变异作物图、活动资源、星砂说明图、宠物日记默认图。
- 后端 `gatewayPath()`：种子/道具图、土地等级图（`/land-assets/*.png`）、宠物日记资源。
- 微信扫码二维码继续通过 Axios 请求 `/api/wx-login/tasks/<task-id>/qr` 后转为 `blob:` URL 显示。

### 3.3 移除管理员登录与改密模块

访问控制已完全交给飞牛，不再需要 `DISABLE_ADMIN_AUTH` 开关，相关代码整体删除：

- 前端：删除登录页 `Login.vue`、用户 store、侧栏「退出登录」菜单与「我的 Token」区块、设置页「修改管理员密码」卡片、路由登录守卫和 401 跳转。旧地址 `/login` 直接重定向到首页。
- 后端：删除 `/api/login`、`/api/logout`、`/api/user/change-password`、`/api/user/me`、`/api/auth/validate`，删除令牌校验中间件、Socket.IO 令牌校验、`admin-store` 与 `auth-security`（登录限流）模块。
- 侧栏用户卡片改为显示当前飞牛用户（来自网关 Header，`/api/fnos/me`）。
- 默认仅允许飞牛管理员访问（HTTP 返回 403，Socket.IO 拒绝连接）；如需让普通飞牛用户使用，可把环境变量 `QQ_FARM_ADMIN_ONLY` 改为 `0` 并把桌面入口 `allUsers` 改为 `true` 后重新打包。
- 旧数据中的 `admin.json`、`login-attempts.json` 迁移时改名为 `*.unused` 保留，不再读取。

## 4. 数据迁移（从 V1.0.x Docker 版升级）

覆盖安装时：

1. `upgrade_init`：若存在并运行着旧容器 `qq-farm-bot`，执行 `docker stop`，并把其重启策略改为 `no`，避免旧容器继续占用 `3007`。**不删除容器和数据卷。**
2. `upgrade_callback`：若新数据目录还没有数据，则：
   - 通过 `docker volume inspect` 找到 `qq-farm-data`、`qq-farm-logs` 的实际路径（找不到时依次尝试 `/var/lib/docker/volumes`、`/vol*/docker/volumes`、`/vol*/@docker/volumes`）；
   - `cp -a` 复制到 `${TRIM_PKGVAR}/data` 与 `${TRIM_PKGVAR}/data/logs`；
   - 写入标记文件 `${TRIM_PKGVAR}/data/.migrated-from-docker`（记录来源路径），之后不会重复迁移。
3. 先卸载 Docker 版、再全新安装本版时，`install_callback` 也会执行同样的迁移。

确认新版本账号与配置都正常后，可手动清理旧 Docker 资源（可选）：

```bash
docker rm qq-farm-bot
docker volume rm qq-farm-data qq-farm-logs
```

> 若迁移失败或找不到数据卷，应用会按全新安装启动，原数据卷保持不变；可把卷中的文件手动复制到 `/vol*/@appdata/qq-farm-bot/data/` 后重启应用。

### V1.1.1 / 内部升级号 2026.10.5（当前）

**问题：** 宠物日记「锦囊」卡片出现 `<img src="" alt="锦囊 113">`，部分道具图片 `404`。

**原因（上游同样存在，与网关前缀无关）：**

- 锦囊图片来自内置活动配置 `pet-diary-2026090101.json`，其中只收录了锦囊 `101`~`105`。游戏新下发的锦囊（如 `113`）在本地配置里没有 `icon_path`，后端返回 `image: ''`，前端直接渲染成空 `src`。
- 道具图片 `getItemImageById()` 对任意 ID 都拼出 `/game-config/seed_images_named/seed_images/<id>.png`。但本地图片只有 1006 张，物品配置里有 61 个道具没有对应图片，于是请求 `404`。
- 变异作物图标目录缺少 `13.png`，对应变异会 `404`。

**修复：**

- 后端：启动后读取一次 `seed_images` 目录，只为本地实际存在的图片返回 `gatewayPath()` 地址，没有图片时返回空串。目录读取失败时保持旧行为。
- 前端：新增 `utils/image-fallback.ts`，内置一张内联 SVG 占位图（不依赖网关路径）。
  - 锦囊图片（宠物日记页、宠物寻宝/护送面板，共 5 处）为空时直接显示占位图，不再出现空 `src`。
  - 全局监听 `<img>` 加载失败（404、空地址），统一换成占位图，只替换一次，避免循环。
- 3007 端口：原生包彻底禁止 TCP 监听（见 3.1）。
  - `cmd/main` 每次启动都会检查并停止仍在运行的旧 Docker 容器 `qq-farm-bot`（不删除容器和数据卷）。
  - 启动后若 `3007` 仍被占用，会在 `app.log` 中记录占用进程。

**排查结果：**

- 前端所有 `src=`、`:src`、`url(`、`background-image`、`new URL`、`import.meta` 引用均已检查：
  - 本应用资源都经过 `gatewayPath()`；
  - 外部头像和 `blob:`/`data:` 地址不受影响。
- 后端返回图片地址的位置只有三处，均经过 `gatewayPath()`：
  - 种子/道具图（`gameConfig`）；
  - 宠物日记资源（`pet-diary`）；
  - 土地等级图（`land-upgrade`）。
- 解包 FPK 核对：服务端托管的静态目录全部存在于 `app.tgz` 中：
  - `server/web/dist`：含 `land-assets` 5 张、`activity-assets/pet-diary` 27 张、`activity-assets/autumn` 2 张、`activity-center/stellar`、应用图标；
  - `server/core/src/gameConfig/seed_images_named`：种子/道具图 1006 张、变异图 15 张。
- 模拟网关抓取：共 770 个图片地址，全部 `HTTP 200`，无 `404`，全部带 `/app/qq-farm-bot` 前缀。地址来源：
  - `/api/config/items|seeds|fruits` 返回的图片；
  - 后端按全部 793 个道具与全部种子生成的图片地址；
  - 宠物日记全部资源、土地等级图、前端全部静态图片。
- 活动配置中引用的 5 个锦囊资源全部能映射到本地文件。
- 无头浏览器验证：空 `src` 与 `404` 图片都会被替换为占位图。

## 7. 升级说明

请通过飞牛应用中心执行：

1. 打开「应用中心」，确认已安装或可安装「Node.js v22」。
2. 选择「手动安装」。
3. 选择 V1.1.1 的 FPK 文件。
4. 确认覆盖升级现有的「QQ 农场」。
5. 安装完成后关闭并重新打开应用窗口。
6. 在应用中打开「设置 → 账号管理」确认账号已迁移。

飞牛应用中心按内部版本号比较升级包。应用显示名固定为「QQ 农场」，内部版本使用 `2026.10.5`，高于此前的 `2026.10.4`，可以覆盖安装。

## 9. 后续维护建议

- 构建：在仓库根目录执行 `fnos/build.sh`，产物与 `.sha256` 在 `fnos/out/`。
- 新增前端图片、字体或下载文件时，避免直接使用以 `/` 开头的地址；应使用前端 `gatewayPath()`。
- 后端向前端返回本应用的资源 URL 时，使用后端 `gatewayPath()`；二维码这类由 Axios 再请求的 API URL 保持相对 `/api/...`。
- 本版本没有应用内登录：不要把 `app.sock` 通过其他方式（端口转发、反向代理）暴露出去。
- 合并上游代码后，重新扫描以 `/` 开头的资源路径，并确认上游没有重新引入登录/令牌相关代码。
- 每次发布都要提高 `fnos/qq-farm-bot/manifest` 中的 `version`。
